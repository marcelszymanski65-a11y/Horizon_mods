## Build it

Horizon's launcher builds a bundle folder itself (it downloads its own Rust the first time):

```bash
horizon-launcher native-build "<this folder>" --trust-native-code
```

Native mods run with your rights and aren't sandboxed: build only code you have read. `cargo test` here runs `runtime.rs`'s own tests without the game.

## Limits

- The mod's own logic that doesn't need the game is translated into `runtime.rs` (`pub mod java`): Translated 128 of 3756 methods (1 more is done another way in Horizon) and 198 of 572 static fields to Rust (46 of those call the game, through Horizon's helpers); 0 of 3 Fabric event handlers. Code that uses Minecraft classes isn't: each helper lists the game calls its Java makes and what they are in Horizon. See `report/translation.md`.
- `BEFORE_CALL`, `AFTER_CALL`, `MODIFY_ARG` and `WRAP_OPERATION` select the called function by name (`selector`), with `require` counted in the target's source. horizon-mixins checks both when it plans: a mismatch fails the build with a message, it never applies silently.
- Raw targets are functions of one Horizon commit (`c9d474dd9116e84c243f8992d75c11314df56f06`): a newer Nightly may move them.


The decompiled source was only used for the conversion and has been deleted.
